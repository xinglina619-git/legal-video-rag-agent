# 法律多模态 RAG Agent 架构说明

## 1. 项目定位

本项目不是“法律判案机器人”，而是一个面向法律咨询准备和纠纷材料整理的 AI 应用 Demo。它帮助普通当事人或法律助理完成三件事：

1. 通过问答补齐关键案情；
2. 将视频、音频、图片、PDF、Word、文本等材料统一整理为可检索、可追溯的证据片段；
3. 结合本案材料和权威依据，生成需要人工复核的初步分析报告。

系统明确不输出胜诉概率，不替代律师判断，不把模型生成内容包装成确定法律结论。

## 2. 总体架构

```text
用户输入层
  ├─ 案情问答
  ├─ 文档：PDF / Word / Markdown / TXT
  ├─ 图片：截图 / 转账记录 / 聊天记录
  ├─ 音频：录音 / 访谈
  └─ 视频：庭审片段 / 现场录像

材料归一化层
  └─ EvidenceSegment
      ├─ content：片段内容
      ├─ source_name：来源文件
      ├─ source_type：text / image / audio / video
      ├─ page_no：文档页码
      ├─ start_ms / end_ms：音视频时间戳
      └─ speaker：说话人字段，预留给说话人分离

索引与检索层
  ├─ Qdrant Evidence Collection：本案材料库
  └─ Qdrant Authority Collection：权威依据库
      ├─ dense embedding
      ├─ sparse embedding
      └─ RRF 融合检索

Agent 编排层
  └─ LangGraph
      ├─ evidence：检索本案证据
      ├─ authority：检索权威依据
      ├─ draft：生成报告草稿
      └─ human_review：人工复核中断与恢复

输出层
  ├─ Markdown 草稿
  ├─ PDF 导出
  ├─ Word 导出
  └─ 引用来源清单
```

## 3. 为什么要先归一化材料

法律材料来源很杂：一份合同可能是 PDF，一段事实可能来自录音，一笔付款可能来自截图，一个关键承诺可能出现在聊天记录里。如果直接把文件扔给大模型，系统会遇到三个问题：

1. 不同材料格式无法复用同一套检索逻辑；
2. 报告中难以说明“这个判断来自哪一页、哪一秒、哪张图”；
3. 多轮分析时需要反复重新处理原文件，成本高且不可控。

因此项目先将所有输入转成统一的 `EvidenceSegment`。后续索引、检索、引用、导出都围绕这个结构进行。这样做的价值是：

- 文档材料可以回链到页码；
- 音视频材料可以回链到时间戳；
- 图片 OCR 内容可以和文本材料一起检索；
- 报告引用可以统一编号，便于人工核验。

## 4. RAG 设计

项目把检索分成两个集合：

| 集合 | 内容 | 作用 |
|---|---|---|
| Evidence Collection | 本案问答、合同、聊天记录、转账记录、录音转写、视频 OCR | 支撑事实梳理 |
| Authority Collection | 法律法规、司法解释、指导案例、官方问答等 | 支撑法律依据检索 |

检索使用 Qdrant 的混合检索：

- dense embedding：适合理解语义相近的表达；
- sparse embedding：适合召回法条关键词、金额、专有名词；
- RRF：融合两类召回结果，提高稳定性。

面试时可以这样解释：法律场景中关键词非常重要，例如“借款”“担保”“劳动合同”“仲裁时效”，纯向量检索可能漏掉精确词；但当事人描述又常常口语化，纯关键词也不够。因此采用 dense + sparse 的混合检索更适合这个场景。

## 5. Agent 工作流

Agent 不是简单的一次 LLM 调用，而是一个可中断的工作流：

1. `evidence` 节点：根据分析目标和案情摘要检索本案材料；
2. `authority` 节点：根据纠纷类型和查询内容检索权威依据；
3. `draft` 节点：只基于检索到的材料生成报告草稿；
4. `human_review` 节点：暂停等待人工确认、修改或驳回；
5. 复核后保存报告状态，并支持 PDF / Word 导出。

这种设计符合高风险领域的产品边界：AI 负责整理和辅助，最终报告需要人工复核。

## 6. 隐私与安全边界

项目在调用在线模型前会遮盖常见敏感字段：

- 手机号；
- 身份证号；
- 银行卡号。

报告提示词要求模型明确区分：

- 当事人陈述；
- 材料能够支持的内容；
- 仍待核实的信息。

系统不输出胜诉率，不输出确定裁判结论，不替代律师或司法人员。

## 7. 当前 Demo 与生产系统的边界

当前版本适合作为 AI 应用开发 Demo，重点展示：

- 多模态输入处理；
- RAG 检索链路；
- Agent 编排；
- 人工复核；
- 引用可追溯；
- 文档导出。

暂不把用户注册、多租户权限、异步任务队列、日志监控、对象存储等作为核心范围。这些是生产化方向，但会明显扩大 Demo 范围。
